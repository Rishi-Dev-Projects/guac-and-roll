## 4. Root Causes
- **Navigation Conflict:** The `<Navigation />` component utilized `sticky` positioning and `backdrop-blur-md`. This caused a new stacking context that restricted any fixed children (i.e., `<MobileMenu />`) to its bounding limits and trapped them underneath other root-level stacking contexts (like `MobileUtilityDock`).
- **Utility Dock Padding:** The global `<main>` content container possessed sufficient padding (`pb-24`) to clear the fixed utility dock, but the sibling `<Footer />` component did not, causing the dock to visually obliterate bottom footer content.
- **Dock Safe Areas:** Hard-coded `bottom-4` values allowed modern iOS home indicators to collide with touch targets.
- **Hero Typography:** Hard-coded `flex` for baseline text blocks ran the risk of overflow on 320px width without a `flex-wrap` fallback.

## 5. Fixes Applied
- Extracted the Mobile Menu's `drawer` and `backdrop` layers out of the sticky `Navigation` tree using `createPortal(..., document.body)`. This guarantees a pure, absolute z-index overlay unaffected by local filter effects.
- Increased `<Footer />` bottom padding (`pb-28 md:pb-12`) to explicitly yield vertical space for the fixed MobileUtilityDock.
- Switched `MobileUtilityDock` to calculate bottom offset using `max(1rem, env(safe-area-inset-bottom))` via an inline style block, guaranteeing hardware safe-zone obedience.
- Injected `flex-wrap` into the Hero `<h1 />` layout logic to gracefully reflow large typography on the narrowest bounds.
